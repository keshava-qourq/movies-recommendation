# Movies recommendation

I want a movie recommendation web app called WatchNext.

A user searches for a movie they liked and the app shows similar movies
they might enjoy, using cosine similarity on the movie's plot, genres,
director and cast. Users can like movies and get a "For you" list based
on everything they liked.

Users sign up and log in with email and password, so their likes are
saved to their account. There are two roles: viewer and admin.
Only admins can upload more movies as a CSV file. The first admin account
is created from the server config.

The app must be fully self-contained: it must not call or depend on any
outside service, API or download, at build time or at run time. That means
no movie APIs, no poster images from the web, no email sending, no
third-party login, and no AI or LLM calls. Ship a built-in sample of about
50 well-known movies with the app, so it works right after install.

Generated by the Quorq AI SDLC platform. Two applications, one repository:

- **`frontend/`** -- the approved app design as a Vite + React SPA. Every screen
  was reviewed and approved, and runs on seeded sample data.
- **`backend/`** -- a FastAPI service. No architecture had been approved
  when this repository was created, so it starts with its health check and
  nothing else.

## Running it

```bash
cd frontend
npm install
npm run dev
npm test          # unit tests (Vitest)
npm run lint       # ESLint
npm run format     # Prettier
```

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload
pytest
ruff check .
ruff format .
```

## Setup

Install: run `npm install` in `frontend/` and `pip install -r requirements.txt` in `backend/`.
Start: run the backend with `uvicorn app.main:app` and the frontend with `npm run dev`.
The database is PostgreSQL, read from `DATABASE_URL`. No other service is needed.
On first start the built-in sample of about 50 movies is loaded once.

## First admin

Set `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` on the server. On startup
the first admin account is created if no user with that email exists. Optionally set
`SMOKE_TEST_EMAIL` and `SMOKE_TEST_PASSWORD` to seed one viewer.

## Session settings

Sign-in returns an opaque session token, sent as `Authorization: Bearer <token>`.
A session expires after 30 minutes without any authenticated request. Each login
creates a new session, and logout revokes only the token used.

## CSV upload format

Admins upload movies as a UTF-8 CSV file with a header row, one movie per row, and
the same columns as the bundled sample catalog (title, year, plot, genres, director,
cast). A movie is unique by lowercased title plus year. Rows are counted from 1
after the header, and errors name the row.

## Known limits

- Sized for about 5,000 movies and hundreds of users, on a single instance.
- One API worker, so the in-memory similarity index stays consistent.
- No email sending, password reset or third-party login.
- Movie listing limit is at most 100 per page.
